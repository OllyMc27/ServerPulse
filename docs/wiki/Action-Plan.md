# Action Plan

Action Plan turns the strongest current signals into prioritised, measurable experiments.

![ServerPulse Action Plan](https://raw.githubusercontent.com/wiki/OllyMc27/ServerPulse/images/action-plan.png)

## Reading a recommendation

Every card includes:

- an opportunity or warning category;
- confidence based on sample quality and signal strength;
- the supporting sample size;
- a plain-language explanation of the evidence;
- a specific next step;
- a link back to the underlying workspace.

Typical actions include scheduling around regional demand, expanding strong rotations, reviewing repeated community requests, investigating weak retention, checking connection losses and reinforcing the official report workflow.

## Use recommendations as experiments

ServerPulse never changes a configuration automatically. Apply one controlled change, record when it started, and compare the same metrics over a similar period. Low-confidence recommendations should be treated as questions worth testing, not facts.

If a recommendation does not match operational knowledge, inspect its evidence and sample before acting. A short event, outage or unusual promotion can temporarily distort otherwise useful signals.
